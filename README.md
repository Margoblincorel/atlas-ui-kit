# Архитектура токенов
В проекте реализована трехуровневая система дизайн-токенов, которая позволяет легко управлять стилями.
1. Первый уровень — Примитивы (например, `--base-blue-700`). Это сырые значения цветов.
2. Второй уровень — Семантика (например, `--color-primary`). Это роли, которые описывают назначение цвета в интерфейсе.
3. Третий уровень — Компоненты (например, `--button-bg-primary`). Это привязка семантической роли к конкретному элементу.

В качестве примера цепочки можно привести путь основного цвета кнопки: примитив `--base-blue-700` превращается в семантическую роль `--color-primary`, затем в компонентный токен `--button-bg-primary` и применяется в CSS-классе `.button--primary`.

# Что реализовано в ходе работы
* Полноценная тёмная тема, которая работает как от системных настроек (автоматически), так и при ручном выборе. Выбор пользователя сохраняется в `localStorage`.
* Все варианты кнопок (primary, secondary, ghost) с проработанными состояниями наведения (hover), нажатия (active), фокуса и блокировки (disabled).
* Поля ввода со стилями для плейсхолдера, состояния фокуса, заблокированного состояния, а также визуализация ошибки через атрибут `aria-invalid`.
* Четыре типа уведомлений: информационное, успешное, ошибка и новое предупреждение (warning).
* Компактный режим плотности интерфейса, реализованный через переопределение компонентных токенов.

# Результаты проверок
* Адаптивность: На ширине 320 px и других заданных разрешениях (375, 768, 1024, 1440 px) контент не обрезается, горизонтальный скролл отсутствует.
* Клавиатура: При навигации клавишами Tab и Shift+Tab фокус четко виден на всех интерактивных элементах.
* Темы: При системной тёмной теме в режиме "auto" страница становится тёмной, при ручном выборе "light" — остается светлой. Выбор сохраняется после перезагрузки страницы.
* Компоненты: Ошибка поля подсвечивается красной рамкой и сопровождается текстом. Кнопки явно отличаются по состояниям hover и disabled. При изменении токена `--color-primary` меняются все акценты на странице.

# Ответы на вопросы
Почему плотность задаётся компонентными токенами?
Плотность влияет только на геометрию (высоту и отступы) конкретных элементов интерфейса. Использование компонентных токенов (например, `--button-height`) позволяет менять эти размеры без дублирования CSS-кода для кнопок или полей. Это сохраняет единый источник правды и позволяет комбинировать компактный режим с любой цветовой темой.

Почему тёмная тема не должна хранить прямые цвета внутри `.button`?
Если прописать прямые HEX-цвета в стилях кнопки, то при смене темы придется переписывать стили для каждого отдельного компонента. Использование семантических переменных (например, `var(--color-primary)`) позволяет менять цвета централизованно в файле `tokens.css`, а все компоненты будут автоматически подхватывать новые значения.
